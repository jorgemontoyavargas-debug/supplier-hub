# Seguridad

## Reporte

Mientras el repositorio no sea público, comunica vulnerabilidades directamente
al propietario del proyecto. Antes de publicar se añadirá un canal privado de
reporte en GitHub Security Advisories.

No abras un issue público con credenciales, documentos o instrucciones de
explotación activas.

## Versiones

Solo la versión más reciente de la rama estable recibirá correcciones durante la
fase inicial.

## Datos sensibles

No adjuntes documentos reales al repositorio. Usa `samples/private`, ignorado por
Git, y anonimiza cualquier muestra antes de compartirla.
